# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 晚到的降级撤销在批次复核区受理：填写业务分组、审批字段、生效日与意见后提交。核验日早于生效日的已签标签照旧保留；系统沿字段依赖重算，超过已签标签的分组停止按低级供数（`SUPPLY_SUSPENDED`），同批仍合格的分组继续可用，不做整批停用。
6. 导出复核证据并保存于交接记录，证据内含撤销台账。

撤销与签发并发时以同一写锁串行：撤销入账后无法再签出偏低标签；已签发批次出现停用分组时转为 `SUSPENDED`，需来源整改后重新执行批次。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
